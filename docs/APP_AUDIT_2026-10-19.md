# Application audit — 19 October 2026

## Assessment and scope

The recruiter workspace has a coherent visual foundation, a useful four-step workflow, and substantial structured evidence functionality. The highest priority is correctness and trustworthy state: several engine paths can present unsupported or failed evaluations as valid hiring signals. A visual redesign should follow those repairs.

This audit reviewed the current working tree, including the pre-existing uncommitted hybrid-screening changes. No application code was changed and no files were deleted. Browser inspection used an isolated SQLite snapshot. Tests used isolated storage. No paid or live model screening was initiated.

Evidence levels below distinguish small synthetic reproductions, browser/API observations, and source inspection. Priorities describe remediation order, not a claim that every issue occurs on every request.

## Highest-priority engine and access findings

### E1 — Provider failure becomes a negative candidate finding

**Priority: critical. Reproduced.** `MatchingAgent` catches a requirement-evaluation exception and returns `not_met`, score zero. The caller then computes and persists an ordinary evaluation. A synthetic provider timeout for one required Python criterion produced **25/100, reject, not_met**. The recruiter run can consequently mark the deep evaluation completed instead of making it retryable.

Represent unavailable evaluation separately from evidence of an unmet requirement. Preserve completed criteria, mark the run partial, and retry only unavailable work. Do not let infrastructure errors contribute to rejection logic.

Source: [matching_agent.py](<D:/Atos - Screening AI Agent Project/backend/agents/matching_agent.py:515>).

### E2 — Citation verification does not constrain the score

**Priority: critical. Reproduced.** A `met` match with a fabricated quotation produced **100/100 and strong_match**, with citation verification zero. Verification changes the quotation flag but does not invalidate its scoring contribution. Empty citation sets also receive a verification score of 1.0.

Separate “quote exists,” “quote supports the criterion,” and “criterion has sufficient evidence.” Unsupported positive findings should require clarification or reevaluation. Report no citations as unavailable coverage rather than perfect evidence verification.

Source: [scoring_engine.py](<D:/Atos - Screening AI Agent Project/backend/services/scoring_engine.py:93>).

### E3 — Missing evaluations can produce a perfect match

**Priority: critical. Reproduced.** Passing no matches for a job containing a required criterion produced **100/100 and strong_match**. Scoring iterates the supplied matches rather than checking complete, unique coverage of the job requirements. Empty scoring buckets default to 100. The legacy path and job editor also permit jobs with no criteria.

Require every active criterion to have exactly one valid evaluation; reject unknown and duplicate IDs. Validate jobs before screening. Normalize category weights around categories actually present so absent preferred criteria do not provide an automatic 25-point bonus.

Source: [scoring_engine.py](<D:/Atos - Screening AI Agent Project/backend/services/scoring_engine.py:88>).

### E4 — The login screen does not enforce API authorization

**Priority: critical before shared or deployed use. Observed and inspected.** Requests without cookies returned HTTP 200 for the candidate list and platform statistics. Both routers lack authentication/role dependencies. The shared password is hardcoded as `1234`, and callers choose their own role. Sessions live in a process-local dictionary.

Enforce identity and permissions at the API boundary, including candidate records, exports, model configuration, local model operations, and deletion. Keep shared demo access explicitly scoped to a demo mode. Persistent or shared sessions are needed before multiple server workers can be supported reliably.

Sources: [recruiter.py](<D:/Atos - Screening AI Agent Project/backend/api/recruiter.py:30>), [login](<D:/Atos - Screening AI Agent Project/backend/api/recruiter.py:64>).

### E5 — Duplicate handling can exclude distinct people

**Priority: high. Reproduced key collision; exclusion confirmed in source.** Two people with the same full name but different email addresses produce the same duplicate key. Screening excludes the later record. It also excludes candidates whose complete semantic evaluation reports are identical, even though an evaluation is not an identity record.

Use document hashes for exact repeated uploads. Treat possible identity matches as reviewable groups, preserve distinct applications, and support choosing or restoring a representative. Do not infer duplicate identity from evaluation output. The inspected existing run showed 636 exclusions; that count alone does not establish how many exclusions were incorrect.

Sources: [duplicate keys](<D:/Atos - Screening AI Agent Project/backend/services/screening_duplicates.py:9>), [name exclusion](<D:/Atos - Screening AI Agent Project/backend/api/recruiter.py:303>), [evaluation exclusion](<D:/Atos - Screening AI Agent Project/backend/api/recruiter.py:255>).

### E6 — Experience calculations disagree and can over-credit tenure

**Priority: high. Partly reproduced.** Improved screening credits a role when any requirement term matches. A Java-only five-year role therefore received five relevant years for the combined terms Java and Python. The deep-evaluation tenure helper separately substitutes **12 months for a role with no stated duration**. The legacy pre-ranking helper can add undated roles to dated periods without proving they do not overlap.

Create one tenure calculation with explicit skill scope, date provenance, overlap handling, and unknown duration. Missing dates must remain unknown. Multi-skill requirements need per-skill duration rules or decomposition into atomic criteria.

Sources: [hybrid tenure](<D:/Atos - Screening AI Agent Project/backend/services/hybrid_screening.py:99>), [invented duration](<D:/Atos - Screening AI Agent Project/backend/services/skill_equivalence.py:601>), [legacy tenure](<D:/Atos - Screening AI Agent Project/backend/services/pre_ranking.py:45>).

### E7 — Zero-weight criteria can still change the recommendation

**Priority: high. Reproduced.** A fully met active requirement plus an unmet, zero-weight required criterion produced **100/100 but borderline**, with one required gap. Weight zero removes the numerical contribution but not gap/rejection checks.

Define zero weight consistently as inactive, or expose a separate enabled flag. Apply the same active-criterion filter to scores, gaps, recommendations, evidence, and displayed counts.

Source: [scoring_engine.py](<D:/Atos - Screening AI Agent Project/backend/services/scoring_engine.py:128>).

## Persistence, recovery, and provenance

### E8 — Saved success and durable success are inconsistent

**Priority: high. Source inspection.** Legacy evaluation, human validation, and interview endpoints catch database failures and still return/cache success. Human validation mutates the cached evaluation before persistence. The recruiter decision endpoint improves this, but its evaluation update and run-payload update are separate transactions.

Use a transaction for related durable changes and report success only after commit. Return a clear recoverable error when saving fails. Avoid mutable caches becoming a competing source of truth.

Source: [evaluation and validation routes](<D:/Atos - Screening AI Agent Project/backend/api/routes.py:834>).

### E9 — Human approval and case identity need one shared enforcement path

**Priority: high. Source inspection.** The recruiter interview endpoint checks its saved approval, but the legacy interview endpoint can auto-evaluate and generate a plan without checking human approval. It also needs to validate that a supplied evaluation belongs to the supplied candidate and job. The interview agent itself does not enforce approval.

Move the intended approval policy and candidate/job/evaluation consistency checks into a shared application service used by both workspaces. If generating a draft before approval is intended, label it explicitly and keep it separate from progression approval.

Sources: [legacy interview route](<D:/Atos - Screening AI Agent Project/backend/api/routes.py:1077>), [recruiter gate](<D:/Atos - Screening AI Agent Project/backend/api/recruiter.py:409>).

### E10 — Background work is only partially recoverable

**Priority: high for larger cohorts. Source inspection.** Ranking and uploads run as in-process background tasks. Ranking has restart detection and retry support, which is valuable. Cohort parsing lacks equivalent startup recovery and a durable work queue. Each upload creates its own four workers; the concurrency limit is per batch, so several batches can multiply load. Reranker timeout stops waiting but does not terminate its worker thread.

Add global admission limits, durable task state, cancellation/checkpoints, and restart recovery for uploads. Use bounded worker execution before raising concurrency. Preserve uploaded work or explicitly identify files requiring re-upload.

Sources: [cohort workers](<D:/Atos - Screening AI Agent Project/backend/services/batch_processor.py:124>), [background submission](<D:/Atos - Screening AI Agent Project/backend/api/recruiter.py:459>), [reranker timeout](<D:/Atos - Screening AI Agent Project/backend/api/recruiter.py:196>).

### E11 — Audit claims exceed recorded evidence

**Priority: high. Source inspection.** The dossier unconditionally declares multiple sections COMPLIANT and describes encrypted demographic storage and append-only logging. The inspected models store JSON fields and allow updates; the dossier generator does not verify those claims. It records the current global model setting rather than the historical model responsible for the evaluation. Human validation overwrites the recommendation, and the dossier then uses that same value for the algorithmic recommendation.

Keep the original model recommendation and immutable decision events separately. Persist actual provider/model, configuration, source hashes, timestamps, and actor identity with each evaluation. Describe the export as an audit dossier and report verified controls and unknowns; a SHA-256 digest by itself does not establish certification or an immutable history.

Sources: [dossier generation](<D:/Atos - Screening AI Agent Project/backend/services/compliance_service.py:99>), [decision overwrite](<D:/Atos - Screening AI Agent Project/backend/db/repository.py:375>), [evaluation persistence](<D:/Atos - Screening AI Agent Project/backend/db/repository.py:257>).

### E12 — Analytics mix demonstration and operational data

**Priority: medium. Source inspection.** The admin token dashboard includes seeded synthetic usage in its analytics. Recruiter processing totals explicitly filter synthetic records, so the two surfaces can disagree. Logs are held in memory despite persistence claims in the module description. Evaluation action accumulators are keyed by an action name, and thread-local action context does not automatically propagate to the requirement worker pool.

Keep demo telemetry behind an explicit demo mode. Persist real events with request/run IDs and propagate context through worker calls. Calculate both dashboards from the same durable event source.

Source: [token_tracker.py](<D:/Atos - Screening AI Agent Project/backend/services/token_tracker.py:74>).

### E13 — Startup and deployment checks are incomplete

**Priority: high before deployment. Source inspection.** Startup uses `create_all`, which does not perform versioned alterations to existing tables. Database startup errors are logged while `/health` continues reporting OK, and health hardcodes fallback enabled. Docker launches Streamlit rather than the current Next.js workspace, and its backend volume persists Chroma but not the default SQLite database. The backend image also copies the entire data directory. Frontend auth always uses same-origin requests while Next rewrites target localhost, so setting a remote public API URL alone does not configure the login proxy.

Apply explicit migrations, distinguish liveness from readiness, configure the server-side proxy destination, package the intended frontend, and persist relational storage. Exclude runtime databases, backups, caches, and personal fixtures from build contexts. Pin a tested dependency set and split runtime, development, legacy UI, and optional observability dependencies.

Sources: [database initialization](<D:/Atos - Screening AI Agent Project/backend/db/session.py:97>), [health](<D:/Atos - Screening AI Agent Project/backend/main.py:143>), [Docker Compose](<D:/Atos - Screening AI Agent Project/docker-compose.yml>), [proxy](<D:/Atos - Screening AI Agent Project/frontend-next/next.config.ts:12>).

### E14 — URL importing needs safer boundaries

**Priority: high before shared use. Source inspection.** Job import accepts arbitrary HTTP(S) destinations, follows redirects, and disables TLS certificate verification. No destination or redirect checks prevent access to private/internal endpoints.

Validate destinations and each redirect, enforce response limits, and restore certificate verification. Keep any exceptional trust configuration narrow and explicit.

Source: [fetch_url_content](<D:/Atos - Screening AI Agent Project/backend/agents/job_parser_agent.py:492>).

### E15 — Candidate deletion does not cover embedded run snapshots

**Priority: high for data lifecycle correctness. Source inspection.** Candidate deletion removes the candidate and relational evaluation/plan relationships, but screening-run JSON embeds evaluations, quotations, decisions, and interview plans without a candidate foreign-key relationship. Deletion does not inspect or redact those payloads. Cached evaluations/plans are also not cleared by the route.

Define retention behavior across relational rows, run snapshots, embeddings, caches, exports, and backups. Use a shared lifecycle service and verify complete removal or explicit retained audit records.

Sources: [delete route](<D:/Atos - Screening AI Agent Project/backend/api/routes.py:1357>), [run payload model](<D:/Atos - Screening AI Agent Project/backend/db/models.py:34>).

## User-side findings and improvements

### U1 — The cohort silently stops at 1,000 candidates

**Priority: high. Observed.** The isolated snapshot contained **1,082 candidates**; the workspace request returned **1,000**. Its 25-row pagination only paginates those downloaded records. The remaining 82 cannot be reached through that list or its search. Existing duplicate filtering further reduces the displayed count without explaining the initial cap.

Use server pagination and search, display total/filtered/selected counts distinctly, and define whether “select all” means the current page or all matching records. Bound API limits and support ranking a selection independently of list-page size.

Sources: [frontend candidate request](<D:/Atos - Screening AI Agent Project/frontend-next/src/lib/api.ts:307>), [workspace query](<D:/Atos - Screening AI Agent Project/frontend-next/src/components/recruiter/workspace.tsx:83>).

### U2 — Simplify the main screening surface

**Priority: medium. Browser observation and source inspection.** The dark theme, restrained blue accent, consistent panels, visible labels, and four workflow stages are a sound foundation. However, the upload area, model/failover panel, mode selector, technical options, comparison controls, and timers compete with the cohort. At the inspected desktop size, the candidate table begins well below the first screen.

Make the main action “Screen selected candidates,” use one recommended mode, and move pipeline versions, cross-encoder pool settings, provider selection, and timer maintenance into advanced controls. Collapse the upload panel after ingestion. Show the active job and selection count next to the primary action.

Source: [verification.tsx](<D:/Atos - Screening AI Agent Project/frontend-next/src/components/recruiter/verification.tsx:71>).

### U3 — Make evidence review faster and more trustworthy

**Priority: medium. Browser observation.** The comparison matrix grows vertically with long reasoning, and save-decision controls appear after the criteria. “Read CV” opens a profile whose score breakdown and evaluations precede the extracted CV. The recruiter dialog shows quotation text but does not connect a quotation to a highlighted source location. Completed deep scores all receive success styling, regardless of recommendation.

Use a persistent candidate header and decision area, concise criterion summaries with expandable evidence, and a direct source/evidence view. Rename “Read CV” if only extracted content is available. Reserve success color for a meaningful supported/approved state. Keep pre-screen score, deep score, evidence coverage, and recruiter decision visibly distinct.

Sources: [review.tsx](<D:/Atos - Screening AI Agent Project/frontend-next/src/components/recruiter/review.tsx:31>), [profile.tsx](<D:/Atos - Screening AI Agent Project/frontend-next/src/components/recruiter/profile.tsx:13>).

### U4 — Preserve context across refresh and support run history

**Priority: medium. Source inspection.** Workflow step and active job are component state. Reload starts at jobs, and the API/UI primarily exposes the latest run for a job. A new run can displace the accessible comparison/decision context. Visited jobs stay mounted to preserve work, which retains all their views and background queries.

Put job, run, and step in the URL. Expose run history and clearly indicate when job criteria differ from the evaluated snapshot. Keep durable work in server state and drafts in an explicit store, allowing inactive views to unmount safely. Warn before abandoning unsaved decisions or job edits.

Source: [workspace.tsx](<D:/Atos - Screening AI Agent Project/frontend-next/src/components/recruiter/workspace.tsx:77>).

### U5 — Improve readability and mobile comparison

**Priority: medium. Browser observation and CSS inspection.** Many supporting labels are 10–12 px. The narrow-screen page stayed within its viewport, but comparison remains a 760 px table inside an approximately 349 px container. Horizontal scrolling is available; comparing and deciding still requires substantial movement.

Increase secondary text where recruiters read evidence, enlarge small actions, keep visible keyboard focus, and provide a stacked comparison or one-candidate review layout on narrow screens. Complete keyboard/screen-reader testing of tabs, navigation, dialogs, tables, and long-task announcements before calling accessibility verified. Existing skip links, native dialogs, error alerts, and reduced-motion CSS are useful foundations.

Source: [recruiter.css](<D:/Atos - Screening AI Agent Project/frontend-next/src/components/recruiter/recruiter.css:253>).

## Efficiency and safe consolidation

1. **Use one shared scoring policy.** Legacy pre-ranking, hybrid ranking, matching guardrails, score calibration, and database reconstruction currently implement overlapping interpretations. The read path even normalizes stored findings without recomputing all their dependent scores. Keep versioned historical results intact and make new evaluations use one explicit policy.
2. **Separate list queries from full records.** Candidate/job relationships use eager `selectin` loading, while the UI downloads broad lists. Fetch summaries and only the latest relevant evaluation for lists; load full CVs, interviews, and historic evaluations on demand. The inspected 1,000-candidate response was approximately 390 KB before HTTP compression.
3. **Avoid retaining every visited workspace.** Replace hidden mounted views with explicit draft/task state and load inactive views on demand. Measure render cost before adding memoization everywhere.
4. **Keep model configuration request-scoped.** V2 freezes targets, but successful fallback still updates shared global settings. Shared clients also contain mutable usage/action state. Persist actual execution provenance and avoid one request changing another request's intended configuration.
5. **Bound and expire caches.** Add embedding-cache retention and schema/version checks, and serialize initial embedding-model loading. The existing process cache has no loading lock, while concurrent upload workers can request it.
6. **Validate bounded evidence against real retrieval quality.** Hybrid evidence has a 40-passage limit and up to four slices per section; qualifications are inserted before work history. Some long work histories can lose relevant evidence. Keep warnings, measure recall on long/multilingual CVs, and reserve or retrieve evidence by criterion. The synthetic benchmark is useful regression coverage, not proof of real-world ranking quality.
